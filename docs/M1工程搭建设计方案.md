> 日期：2026-09-24

## 1. 工程目标

1. 用 **Taro 4 + React + TypeScript** 建一套代码，编译出：
   - 阶段一：**H5**（手机竖屏操控端 + 平板/电脑横屏投屏端）
   - 阶段二：同一工程加编译目标出**微信小程序**（仅新增适配层，核心不动）
2. 全部**业务数据本地存储**，零云端依赖、完全离线可用。
3. **核心逻辑纯 TS、无 UI 依赖**：状态机 / 夜间结算 / 胜负判定 / 积分引擎 / 计时引擎全部可单测，方便二期小程序与多端复用。

## 2. 技术选型明细

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | Taro 4.x（React 18 + TypeScript 5） | 一套代码 H5 + 微信小程序；已确认 |
| 包管理 | npm（Taro 默认） | 免额外工具链 |
| UI 组件 | NutUI-React-Taro + 少量自研组件 | 中文生态好、对 Taro 4 兼容；投屏页以自研布局为主 |
| 状态绑定 | zustand | 轻量；store 可在非 React 环境读写，天然契合「核心逻辑与 UI 解耦」 |
| 单测 | vitest | 原生 TS/ESM、零配置、快；只测 `src/core` |
| 本地存储 | 自研 StorageAdapter：H5 走 localStorage（小）+ IndexedDB（大，原生 API 封装）；二期小程序端换成 `Taro.getStorage` 实现 | 接口统一，二期只换实现 |
| 路由 | Taro 内置路由；两个入口页 `/pages/judge/*`、`/pages/display/index` | 操控端与投屏端同工程、不同入口 |
| 计时 | 自研 TimerEngine（`Date.now()` 时间戳基准，防 setInterval 漂移） | 支持分阶段、暂停/续播、提示音点 |
| TTS | 自研 TtsAdapter：H5 用 Web Speech API（系统默认中文语音，免费离线） | 二期小程序替换实现，接口不变 |
| 音频 | HTMLAudioElement 播提示音/铃声（资源文件自带） | 与 TTS 分离，铃声不受 TTS 占用影响 |
| 多端同步（阶段一） | 自研 SyncAdapter：`BroadcastChannel`（同设备双标签零配置） | 跨设备投屏方案见 §10.3，预留接口 |

## 4. 核心类型设计（types.ts 草案）

```typescript
// 阵营与身份粒度
type Camp = 'wolf' | 'god' | 'civ';
type RoleId = 'werewolf' | 'wolfKing' | 'wolfBeauty' | 'gargoyle' | 'trickWolf'
  | 'wolfWitch' | 'bloodMoon' | 'mechWolf' | 'nightmare'
  | 'seer' | 'medium'              // 通灵师：查验具体身份，与 seer 同构
  | 'witch' | 'hunter' | 'guard' | 'idiot' | 'gravekeeper'
  | 'dreamWeaver' | 'demonHunter'  | 'pureWhite' | 'mathematician' | 'knight' | 'civilian';

// 夜间行动类型（≈20 种，覆盖规则文档 §7-2/3）
type NightActionKind = 'none' | 'confirmRole' | 'confirmStatus'
  | 'checkCamp' | 'checkIdentity'        // 预言家/通灵师/石像鬼/狼巫/纯白
  | 'kill' | 'emptyKill'                 // 狼刀/空刀
  | 'save' | 'poison' | 'guard' | 'dream' | 'fear' | 'hunt'
  | 'trick' | 'mathCheck' | 'learn' | 'charm' | 'duel' | 'doubleKill';

interface Role {
  id: RoleId; name: string; camp: Camp;
  nightAction: NightActionKind;
  defaultSeconds: number[];              // 分阶段时长：[90] 或 [15,15]
  wakeEveryNight: boolean;               // 白痴次夜不唤醒等
  canSuicide: boolean;                   // 自爆权限（石像鬼/诡狼不可）
  shotRule?: 'onDeath' | 'restricted';   // 猎人/狼王开枪限制
}

interface BoardConfig {
  id: string; name: string; playerCount: 12 | 15;
  seats: { role: RoleId; count: number }[];
  winMode: 'tuBian';                     // 屠边
  timingPack: 'shandong' | 'moka';       // 夜间时长包：手册 90/45 或摩卡 60/30
  scorePack: 'shandong' | 'moka';        // 行为分/投票分上限差异包
  mechPoisonIgnoresSave: boolean;        // 机械狼学得毒药是否无视解药（默认 false）
}

// 一次夜间行动的结构化记录（法官点选产出）
interface NightAction {
  night: number; role: RoleId; actorSeat: number;
  kind: NightActionKind; targets: number[];   // 座位号
  detail?: Record<string, unknown>;           // 查验结果/学得技能/双刀…
}

interface Player {
  seat: number; name?: string;               // 姓名可空
  role: RoleId; alive: boolean;
  deathCause?: string; revealed: boolean;    // 白痴翻牌/骑士决斗翻牌等
  badge: boolean;                            // 是否警长
  mech?: MechWolfState;                      // 机械狼专属状态机
}

// 机械狼状态机（规则文档 §7-4）
interface MechWolfState {
  learned: false | { targetSeat: number; skill: 'none' | 'checkIdentity' | 'poison' | 'guard' | 'shot' | 'doubleKill' };
  poisonUsed: boolean; doubleKillUsed: boolean; hasKnifeRight: boolean;
}

type GameStage =
  | 'setup' | 'assign'
  | { phase: 'night'; night: number; step: number }     // step=角色行动序号
  | { phase: 'dawn'; night: number }                    // 死亡公告
  | { phase: 'sheriff'; day: number }                   // 警长竞选（仅首日白天）
  | { phase: 'speech'; day: number }                    // 放逐发言
  | { phase: 'vote'; day: number; round: 1 | 2 }        // 投票/PK
  | { phase: 'lastWords'; day: number }
  | { phase: 'settle' };

interface GameState {
  id: string; boardId: string; stage: GameStage;
  players: Player[]; nightActions: NightAction[];
  votes: VoteRecord[]; sheriff?: number;               // 警徽持有者座位
  winner?: 'wolf' | 'good'; winReason?: string;
  createdAt: number; updatedAt: number;
}
```

## 5. 状态机设计（stateMachine.ts）

```text
setup → assign
      → night(n).step[0..k]          # 按版型唤醒序列逐角色（含分阶段：石像鬼 15+15、诡狼 10+15）
      → dawn(n)                      # 生成死亡公告 → winJudge?
      → sheriff(1)                   # 仅第 1 天：上警/竞选发言(90s)/警徽投票记录
      → speech(n) → vote(n,1)        # 放逐发言(90s/警长120s) → 戴盔 5s 投票
        ├─ 平票 → speech(PK) → vote(n,2)   # PK 一轮
        ├─ 出局 → lastWords?          # 遗言 90s（按出局规则）
        └─ winJudge? → 未分胜负 → night(n+1)
      → settle                        # 胜负 + 积分结算 + MVP/SVP/背锅 + 扣分
```

- 事件：`start / pause / resume / next / back / jump(stage) / recordAction / recordVote / end`
- **回退**：每次迁移前压栈快照，`back` 弹栈恢复（含计时位置）
- **持久化**：每次迁移后序列化 GameState 到本地，支持断点续局
- **顺序注入**：夜间唤醒序列由版型+存活状态计算（梦魇先于狼队、石像鬼/诡狼/机械狼单独唤醒、白痴首夜后不再唤醒）

## 6. 夜间结算引擎（nightResolver.ts）

- **输入**：本夜全部 NightAction（点选结构化）；**输出**：`{ deaths: {seat, cause}[], checks, scoreEvents[], sideEffects }`
- 处理顺序：梦魇恐惧 → 狼队刀（含机械狼获得刀人权后）→ 石像鬼/诡狼特殊阶段 → 守卫/摄梦 → 女巫解药/毒药 → 查验类（预言家/通灵师/狼巫/纯白/数学家/石像鬼）→ 守墓人信息 → 产出
- 冲突规则（全部写进 resolver，单测覆盖）：
  - 同守同救 → 出局且解药视为已用
  - 同刀同毒（不同阵营冲突）→ 以技能发动过程结算行为分
  - 同狩同毒（同阵营冲突）→ 以实际死亡原因结算
  - 梦游吃毒/毒杀猎魔人（毒药无效且视为已用）→ 好人失误标记，影响特殊分
  - 机械狼学守卫：女巫毒药打到其守护目标 → 反弹毒死女巫
  - 血月使徒自爆 → 下一夜神职无法发动技能；最后狼被放逐 → 再入夜
  - 摄梦人：连两夜同目标梦亡；摄梦人夜间出局 → 当夜梦游者同亡（猎人被梦亡不能开枪）

## 7. 胜负判定（winJudge.ts，纯函数）

`evaluateWin(state) → null | { winner, reason }`，四条规则按序判定：
1. 狼全灭且神、民均有存活 → 好人胜
2. 同一夜间双方同时达成 → 狼人胜（在 resolver 产出后调用，按同夜口径）
3. 神或民任一阵营全灭且狼有存活 → 狼人胜（屠边；白痴翻牌未最终出局前仍计神阵营存活）
4. 白天放逐发言开始时狼队最高票 ≥ 其他身份最高票 → 狼人胜（拍刀）

## 8. 积分引擎（scoring.ts）

- **规则表驱动**：`ScoreRule { id, role?, appliesTo(board), when(event) => boolean, value, cap?, enabled }`
- 输入 GameState 全量记录 → 逐项产出 `ScoreRecord { seat, ruleId, value, reason }`：
  - 胜负分 +5/0
  - 13 角色行为分（含上限、豁免：吞毒自爆/同时梦亡不加等）；通灵师套预言家方案、机械狼 +0.5/−0.5
  - 投票分：放逐投狼 +0.5（上限随 scorePack 1/2）；投好人/弃票 −0.5；4 条 PK 计票规则；不计票身份按版型生效（预言家/通灵师/纯白/狼）
  - 特殊分：点狼/点神（12 人 4 张 +1、15 人 5 张 +2）、拍刀 +0.5、连刀 +0.5、好人零失误 +1（失误情形排除）、狼拿警徽 +0.5
  - 评选：MVP +2 / SVP +1.5 / 背锅 −1（首批法官手动录入）
  - 违规扣分：手动录入（类型+分值，参考手册处罚标准表）
- 输出 = 单局 ScoreRecord[] + 累计 PlayerTotal（存 historyStore），结算页逐项展示并允许法官微调（留痕）

## 9. 本地存储设计

```text
localStorage:  configs(版型/时长/积分/发言) + ranking(累计积分)
IndexedDB :    games/{id} → GameSnapshot 全量（对局可能大）
```

- `StorageAdapter` 接口：`get/set/remove/keys/exportAll`
- 每次状态迁移自动保存（防抖 300ms）
- **导出**：`share.ts` 导出整包 JSON（H5 `a[download]`）；结果分享图用 canvas 绘制长图导出 PNG
- 二期小程序：Adapter 换 `Taro.setStorage` + 文件系统，接口不变

## 10. 页面与交互要点

### 10.1 操控端（手机竖屏）
| 页面 | 关键交互 |
| --- | --- |
| setup | 选版型 → 座位表（1–12/15，姓名可空，赛中可调）→ 随机/手动发身份；身份**点按显示/一键全隐** |
| night | 大字口令「请{角色}睁眼」→ 分阶段倒计时 + 铃声 → 点选录入（目标座位+行动类型）→ 暂停/回退 |
| day | 死亡公告（自动文案）→ 发言计时（90/90/120/90，剩 30s 提示、结束提醒）→ 警徽票记录 → 放逐投票点选票型（含 PK 轮次）→ 遗言 |
| settle | 胜负+逐项积分明细+MVP/SVP/背锅录入+违规扣分+手动微调 |
| ranking / history / config | 累计排行、历史+导出、规则可视化配置 |

### 10.2 投屏端（横屏）
- 独立入口 `/pages/display/index`：当前阶段、**倒计时大字**、**存活图**（座位圆点图）、**票型统计**；**绝不出现身份信息**，不显示积分榜

### 10.3 阶段一同步方案（SyncAdapter）
- **同设备双窗口**（手机/电脑同机）：`BroadcastChannel` 广播 GameState，投屏页只读订阅——零配置、零依赖，先支持这种
- **跨设备**（手机操控 + 平板/电脑投屏）：预留 `SyncAdapter` 接口；两个备选：① 操控端起极简局域网 WS 中继（小工具）；② WebRTC 直连。方案待实施前选定，不阻塞主体开发（接口先行）

## 11. 计时与播报

- **TimerEngine**：`timeline = [{label, seconds, chimeAt?[]}]`（如狼人 [90s, chimeAt:30s]、石像鬼 [15s, 15s]）；`Date.now()` 基准防漂移；pause/resume；到点触发提示音/铃声
- **口令计时口径**：TTS 口令播完回调 → 计时开始；铃声结束 → 计时停止（对齐手册起止规则）
- **TtsAdapter**：`speak(text)`，口令模板库（请睁眼/请闭眼/天亮了/警长竞选开始…），H5 用 `speechSynthesis` 系统默认中文音色

## 13. 实施执行清单（评审通过后按序执行）

1. 环境检查：Node 18+（Taro 4 要求）、npm；`npm i -g @tarojs/cli`
2. `taro init werewolf-judge`（React + TS + npm），跑通 `dev:h5` 空页
3. 建目录骨架；落 `core/types.ts`
4. 规则数据落盘：`roles.ts`（22 角色）、`boards.ts`（13 版型）、`scoreRules.ts`（两套分值包）
5. `timer.ts` + 单测
6. `stateMachine.ts` + `persist.ts` + 单测
7. `nightResolver.ts` + `dayResolver.ts` + `winJudge.ts` + 单测（§12 用例）
8. `scoring.ts` + 单测
9. `services/`（storage/tts/audio/sync/share）+ zustand stores
10. 页面骨架 9 页 + 路由 + 两个入口（judge / display）
11. `npm run dev:h5` 联调：跑通一局「预女猎白」全流程（不挑 UI）
12. 验收：对照规则文档 §5 手工对 3 个 golden 积分场景

> 本里程碑只做骨架与核心引擎，页面做到「能用不挑 UI」；UI 打磨、语音口令、分享图美化在 M4。

## 14. 风险与约束

| 风险 | 对策 |
| --- | --- |
| Taro 4 与依赖（React 18/NutUI）版本兼容 | 初始化时锁版本；NutUI 不兼容则退回自研基础组件 |
| 机器 Node 版本未知 | 第 1 步先检查，低于 18 先装 nvm-windows/Node LTS |
| 跨设备投屏同步方案未定 | SyncAdapter 接口先行；阶段一以同设备双窗口跑通，跨设备在 M4 前定 |
| Web Speech 中文语音个别系统缺失 | TtsAdapter 内降级（静默+视觉提示），不阻塞流程 |
